# ExpenseFlow

Company expense management: employees submit expenses, managers approve them, finance tracks
budgets and pays reimbursements.

This is a monorepo: the frontend, the backend and the code they share live in one repository and
are installed with one command.

| Part     | Folder            | Tech                                        |
| -------- | ----------------- | ------------------------------------------- |
| Frontend | `apps/web`        | React 19, Vite, TypeScript, React Router    |
| Backend  | `apps/api`        | Node.js, Express 5, TypeScript, Prisma, Zod |
| Database | `infra/docker`    | PostgreSQL 17 (runs in Docker)              |
| Shared   | `packages/shared` | Types, enums, constants and Zod schemas     |
| Tooling  | `packages/config` | Shared TypeScript and ESLint settings       |
| Monorepo | repo root         | pnpm workspaces + Turborepo, Prettier, CI   |

## Getting started

### 1. Install the tools (once)

- [Node.js 22](https://nodejs.org/) — if you use nvm, run `nvm use` in the repo
- pnpm — `npm install -g pnpm`
- [Docker](https://docs.docker.com/get-docker/) — for the local database
- VS Code is recommended; accept the suggested extensions when it asks

### 2. Set up the project

```bash
git clone git@github.com:Rediet-W/expenseflow.git
cd expenseflow
git switch dev

pnpm install                              # installs everything for every app
cp apps/api/.env.example apps/api/.env    # backend settings
pnpm db:up                                # starts PostgreSQL in Docker
pnpm db:migrate                           # creates the database tables
```

### 3. Run it

```bash
pnpm dev
```

- Web: http://localhost:5173 — should say **API: ok · Database: up**
- API: http://localhost:4000/api/health

If the page says the database is down, check that Docker is running and run `pnpm db:up` again.

## Commands

Run these from the repo root. They run for every app at once.

| Command           | What it does                                     |
| ----------------- | ------------------------------------------------ |
| `pnpm dev`        | Starts the web app and the API with live reload  |
| `pnpm lint`       | Checks code for mistakes (ESLint)                |
| `pnpm typecheck`  | Checks TypeScript types                          |
| `pnpm test`       | Runs all tests (the API tests need `pnpm db:up`) |
| `pnpm build`      | Builds everything for production                 |
| `pnpm format`     | Formats all files with Prettier                  |
| `pnpm db:up`      | Starts the local PostgreSQL database             |
| `pnpm db:down`    | Stops it (your data is kept)                     |
| `pnpm db:migrate` | Applies schema changes and creates a migration   |
| `pnpm db:studio`  | Opens Prisma Studio to browse the database       |

To run a command for one app only, add a filter:
`pnpm --filter @expenseflow/api test` or `pnpm --filter @expenseflow/web dev`.

### Backend modules

Each folder in `apps/api/src/modules/` is one feature, and every feature follows the same split.
`modules/health/` is a complete working example to copy.

```
modules/expenses/
├── expenses.routes.ts      URL → controller (GET /api/expenses …)
├── expenses.controller.ts  reads the request, calls the service, sends the response
├── expenses.service.ts     the business rules and database queries (no req/res here)
└── expenses.schema.ts      Zod schemas that validate request bodies and params
```

Then register the router in `src/routes/index.ts`. To return an error, `throw new AppError(...)`;
the error handler turns it into the standard error response.

Modules: `auth`, `users`, `departments`, `categories`, `expenses`, `approvals`, `budgets`,
`reimbursements`, `notifications`, `reports`, `dashboard`, `audit-logs`.

### Frontend features

Each folder in `apps/web/src/features/` matches a backend module and holds everything for that
feature:

```
features/expenses/
├── api/          calls to /api/expenses (using lib/api-client.ts)
├── components/   components only this feature uses
├── hooks/        hooks only this feature uses
└── pages/        full pages, registered in src/routes/router.tsx
```

If something is needed by two or more features, move it up to `src/components`, `src/hooks` or
`src/services`.

### Shared code

Anything both apps need to agree on goes in `packages/shared` and is imported from
`@expenseflow/shared`: request/response types, enums like expense statuses and user roles, and Zod
schemas. Define a schema once there; the API uses it to validate and the web app uses it for forms.
